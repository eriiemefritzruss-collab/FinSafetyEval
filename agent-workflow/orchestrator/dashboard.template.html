    职责结构 · 实际进度以当前实况为准

    一个对话入口，后台独立执行与核验

    Windows Planner 直接写 GitHub 事件；Mac 唯一 controller 领取实施及独立 Review 工作；Windows notifier 读取结果并回送固定入口。直接 daemon fleet 连接不作为本链路的必需条件。

    固定入口

    Windows · Planner 对话

    持续提交需求、冻结计划并查看回传结果。

    1. 每项需求独立任务ID
    2. 计划进入共享事件记录
    3. 用户明确批准有效版本
    4. notifier回送并记录关联ACK
    →

    共享事实

    GitHub · 任务与证据

    完整版本绑定和报告供两端读取。

    1. 需求、计划与批准事件
    2. 实现head/base、CI及报告
    3. 返工分类与新版本记录
    4. 结果通知和入口ACK分别留痕
    →

    后台角色

    Mac · 唯一controller

    SQLite持久去重，工作目录与角色分离。

    1. 获批才派发Implementer
    2. 就绪后启动新Reviewer
    3. 旧head结论失效，按原因返工
    4. PASS进入待用户合并，保留原对话ACK阶段
    入口收到ACK不代表用户已读；READY_FOR_HUMAN_MERGE不代表已送达或已合并。最终合并始终由用户确认。

    文件快照不自动刷新。本机HTTP模式由浏览器每10秒重新读取同一HTML；可用顶部链接暂停。页面没有fetch、后台状态写入或操作按钮；controller更新快照与浏览器刷新分别运行。
